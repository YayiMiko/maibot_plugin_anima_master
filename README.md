# MaiBot Anima 绘图大师

独立 MaiBot 插件，基于 [Anima Master](https://github.com/YayiMiko/anima-master)
的 `main @ 4f6a0f1`（0.9.3 后白底回档）。原 AstrBot 插件不改动。
目前已接入普通／多人生图、引用图、法术解析、反推和聊天预设管理，版本号 0.1.1。
这是独立的 MaiBot 移植仓库，不是 AstrBot 插件的替代安装包。

## 当前可用

```text
/anm
/anm 红裙少女
/anm 生图 白色小猫坐在窗边
/anm 多人 两名少女牵手站立
/anm 无优化 1girl, red dress, white background
/anm 横图：少女站在花园里
/anm 无优化 1girl, standing --尺寸 1216x832
/anm 状态
/anm 解析法术（附图或引用含图片的消息）
/anm 反推（附图或引用含图片的消息）
```

保留 `/anima` 和 `/comfyui` 前缀。只匹配明确的指令，不通过普通聊天隐式触发。
帮助只展示一个状态入口；诊断和调试状态仍保留，调试只看调用者自己的记录。

普通生图复用 Anima 的提示词扩写、角色匹配、画师与画风、Danbooru 校正、Tag
清洗、白底立绘和 Turbo 策略。没有明确背景时沿用白底规则。固定角色只有明确
点名时才注入；原样模式直接使用用户 tags，不调用 LLM、不补默认画师或背景。
配置中已有的角色和预设可以继续使用，聊天中也可以管理它们。

### 画师与角色

```text
/anm 查看画师预设
/anm 创建画师预设 名称=@artist_a, @artist_b,
/anm 切换画师预设 名称
/anm 设置画师预设 @artist_a,
/anm 追加画师预设 @artist_b,
/anm 删除画师预设 名称
/anm 查看角色
/anm 查看角色 名称
/anm 添加角色 名称=1girl, red hair,
/anm 删除角色 名称
```

新建命名画师预设会保存并启用；追加未指定名称时作用于当前画师预设或默认画师。
同名角色会被更新。角色不提供全局自动选中，仍需在生图描述中点名使用。
所有操作都沿用插件普通使用权限，不单独增加管理员门槛，也不会调用 LLM。

SDK 当前没有公开的配置持久化写接口，因此聊天修改原子保存于插件数据目录的
`chat_presets.json`，不改写宿主 `config.toml`。这些设置在插件各会话间共享，
重载后保留；已接受的生图任务继续使用原配置快照。聊天修改的字段优先于宿主
同名字段，再应用原千代／Turbo 预设规则；预设派生的默认内容仍遵循上游行为。
宿主修改被覆盖时，可用 `/anm 重置聊天预设 确认` 清空聊天覆盖并恢复宿主配置。
重置会移除聊天新增的角色和画师，不会删除宿主配置、图片或任务记录。
最近 128 条修改指令记录去重编号；损坏的预设文件不会被静默覆盖。

多人模式复用原插件的 2～4 人结构化规划、人物身份描述与共享场景互动策略；
规划无效或人数不符合明确要求时不提交生图，不降级到普通路径。只有文字规划
阶段最多一次修正请求，不会因此重复采样。未指定背景仍使用简单白底。
`/anm 多人 无优化 <tags>` 与关闭提示词优化时沿用上游直通行为，不执行多人规划。

引用图仅从本次消息及同一会话的明确引用读取，引用图片优先；本阶段一次使用
一张图。保留原始字节和生成元数据，解析 ComfyUI、WebUI 与 JSON 生图信息。
法术解析不会调用 LLM，也不会自动反推；QQ 压缩导致元数据消失时会明确报告。
反推通过 Host 视觉模型生成英文 tags。附图或引用图辅助生图优先读正面元数据，
没有时再视觉反推；没有图片、读取失败或反推失败时不偷偷替换图片或提交生图。
无优化／关闭优化时不追加图片描述，保持文字直通。背景判断仍依据原始用户要求，
参考图背景不会自动取消白底规则。这里只提取参考描述，并非像素级图生图。

**改图尚未开放。** 原来的人物视觉验证和候选重试尚未移植，
本阶段不会进行生成后的自动视觉校验或重新生成。

## 安装与配置

目标版本：MaiBot 1.3.1 / Plugin SDK 2.8.2，Python 3.12+。
将本目录放入 MaiBot `plugins/`，安装 `pyproject.toml` 所列依赖。
新安装可复制 `config.example.toml` 为 `config.toml`，其它字段由 SDK 补齐。
群白名单仍由宿主控制；本插件不会扩大聊天权限。

文本规划调用公共 `ctx.llm.generate`，默认使用 Host `utils` 任务；可在 `maibot`
组填写 `prompt_model_name`，选择 Host 已配置的具体模型。只发送插件的 system/user
提示词，不注入聊天人设、聊天历史或自动加狐莉。模型密钥由 Host 管理。
旧 AstrBot Provider ID 不适用；深度思考选项由 Host 模型配置控制，旧参数不透传。
图片反推默认走 `maibot.vision_model_task = "vlm"`，也可用 `vision_model_name`
指定宿主已配置的多模态模型。视觉模型只需支持图片输入和非空正文，
无需支持工具调用；宿主的综合能力测试未通过工具调用，不等于识图不可用。
原深度思考开关在 MaiBot 配置界面隐藏，实际推理行为只由宿主模型配置决定，
不会因为旧开关开启而重复调用同一个模型。

ComfyUI 地址必须是 MaiBot 所在机器可访问的地址。插件不会启动 Windows ComfyUI。
工作流构建、模型、LoRA、采样与尺寸契约复用上游；不为移植改变默认画风。
本阶段对自定义工作流只提供上游绑定契约，未做用户工作流实机验收。

### 配置迁移

```text
python tools/migrate_config.py /path/to/astrbot_plugin_anima_master_config.json /path/to/new/config.toml
```

支持旧平铺和 `anima_master_*` 分组配置，迁移已知参数、角色和画师预设；拒绝覆盖
已有目标文件。不复制 API 密钥、旧任务、聊天记录或登录凭证，关闭无意义的远程
自动启动设置。Tavily 搜索需要另填 `maibot.research_api_key`；未配置则跳过可选
搜索，Danbooru 校正单独工作。不要把运行配置加入 Git。

## 任务和发送

后台任务使用独立配置快照、独立输出目录和逐消息去重，采样串行提交；状态查询
不等待采样锁。下载与记录使用原子替换，保存 ComfyUI prompt ID。成功只发送图片；
图片发送的 SDK RPC 等待为 180 秒；部署时应同步协调消息网关与 OneBot 的内层
超时，不能只延长外层等待，详见[部署说明](docs/deployment.md)。
回执不确定时记录并通知，不自动重发。重载会取消本地等待并分类记录任务状态，
不会全局中断 ComfyUI，也不会自动重提原任务。与 Qwen 使用独立的数据和队列，
最终 GPU 排队交给 ComfyUI。

已向 ComfyUI 提交、但超时或重载后未确认结果的任务记录为 `remote_unknown`；
已开始发送的任务记录为 `delivery_unknown`，两者不会混为确定生成失败。
辅助受理／优化警告发送失败不会阻止生成。任务私有记录包含随机 seed、采样参数、
实际工作流图和阶段耗时；自定义多阶段工作流以保存的图为准。

```text
/anm 核对任务
/anm 恢复任务
/anm 核对任务 <完整任务编号>
/anm 恢复任务 <完整任务编号>
```

不填写编号时使用当前会话、当前用户最近的生图任务；完整编号可用隐藏的
`/anm 调试状态` 查看。核对只查询旧任务的历史和队列，不发送图片。
恢复仅在你明确请求时下载已完成但未尝试发送的旧结果，不新建采样任务。
已发送、回执不明、正在执行或已被恢复的任务不能重复恢复发送。
没有 ComfyUI 编号、历史已清除或私有配置快照已丢失时不承诺恢复。
状态／诊断有独立查询名额，不受生图满队列影响；诊断仍隐藏于帮助之外，
提供脱敏连接、DNS、排队与发送等待信息，自定义工作流显示“提交时校验”。

### 数据保留

`comfyui_connection.storage_retention_days` 默认 30 天，设为 0 停用时间清理。
加载插件时检查一次，随后每小时检查；配置热更新在下一次检查生效。
只删除已结束且过期的任务记录和对应任务目录里的输入、输出与配置快照。
任务创建时间、记录更新时间和目录内文件均需过期；正在执行和发送中的任务跳过。
聊天预设、宿主配置、共享 QQ 缓存、Qwen 输出和原 AstrBot 数据不会被清理。

清理按批次轮转，每次最多扫描 1000 条记录、删除 64 个任务；含符号链接或
Windows 联接点、过大的目录、损坏记录、未知状态及无对应记录的孤立目录保留，
避免通过异常路径误删。不会读取任务记录中的输出路径来决定删除对象。
清理日志仅记录任务编号和数量；过期删除不可恢复，生图消息去重也随记录到期结束。
需要长期保留的图片请另行导出，或停用时间清理。本次仅以临时目录测试，
尚未对真实运行数据执行清理。旧 `manifest_max_records` 不适用于此处的独立任务
存储，因此在配置界面隐藏；不维护全局图片清单或“最新图片”。
目录枚举按批次推进，不先读取和排序全部记录；清理和加载时的历史读取在后台线程
执行。调试状态读取每个会话与用户的最近生图索引，不再逐条读取全库。
`remote_unknown` 不属于已结束状态，保留待人工核对，不进行过期删除。

## 离线验证

```powershell
uv sync --dev
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
```

测试禁止真实 HTTP 访问，LLM、采样进程和 QQ 发送均使用替身。父目录存在未解决
的 pyproject.toml 冲突时，使用独立 venv，不修改父项目。离线通过不等于服务加载、
QQ 端到端或图像质量验收。2026-10-03 在用户授权的测试群完成普通生图、
两人互动生图、引用图片法术解析、含／不含元数据的视觉反推、参考描述生图、
重复消息拦截、无图不回退以及角色／画师预设增删和重载检查。
用户确认过真实指令的收图；自动验收调用同一命令处理函数并使用真实 SDK、
模型、ComfyUI 和 QQ 发送，不等于模拟一条人类入站消息。

一次参考生图发生发送未确认，随后延长发送链路超时。新图发送测试取得 QQ
消息 ID，发送耗时约 12.7 秒，没有重试。该样本未超过旧超时门槛，
一分钟以上上传仍未验证；不宣称网络问题或所有超时均已解决。
自定义工作流实机验收、3～4 人画面质量和长时间运行稳定性仍待验证。
